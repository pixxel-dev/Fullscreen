## 2025-05-18 - Foreground Overlay Subsystem & Dual Display Windowing
**Implicit Logic:** `ForegroundOverlayService` dynamically targets LynkCo secondary displays by hardcoding `Display ID 1003`. When available, it uses `createDisplayContext` and `createWindowContext(TYPE_APPLICATION_OVERLAY)` to mirror float buttons across screens with inverted horizontal gravity (`START` vs `END`). Toggling "fullscreen" for target apps does not modify app window parameters directly; instead, it re-launches the target application's launch intent with `ActivityOptions.setLaunchDisplayId(1003)` and `FLAG_ACTIVITY_NEW_TASK | FLAG_ACTIVITY_CLEAR_TOP`. Furthermore, temporary focus shifts to system apps (`com.android.launcher3` and `com.android.systemui`) are explicitly ignored during `UsageStatsManager` 1s polling to prevent button state flickering.
**Impact:** Documentation must clarify that fullscreen mode relies on OS activity launch flags on secondary virtual display ID 1003 rather than system window flag modifications. Developers modifying overlay behavior or app package filtering need to account for dual-display window context bounds and system UI focus exceptions.
